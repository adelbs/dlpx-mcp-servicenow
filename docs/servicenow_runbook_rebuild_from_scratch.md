# Runbook — Rebuilding the ServiceNow configuration from scratch

Step-by-step guide to rebuild the entire Delphix ↔ ServiceNow demo environment configuration, in case the PDI
instance expires, is lost, or you need to set up a new one. Follows exactly what was done in the first setup.

---

## 0. Prerequisites

- Account at [developer.servicenow.com](https://developer.servicenow.com) (the same account can only have one
  active PDI at a time).
- Admin access to the instance (user `admin`, password auto-generated by ServiceNow).

---

## 1. Requesting/waking up the PDI instance

1. Go to `https://developer.servicenow.com` and log in.
2. In the top right, click **Request instance**.
   - If an instance already exists, this button leads straight to the "Manage my instance" screen with its
     status.
   - If none exists, it opens the **"Request an Instance"** modal.
3. In the modal, choose the available release (usually only the most recent one is enabled; older releases
   typically show "No instances available" and can't be selected).
4. Click **Request**.
5. The **"Manage my instance"** screen shows "Fulfilling Request... Your personal developer instance (PDI) is
   currently being prepared." — takes 1 to a few minutes. You can refresh the page or wait for the notification.
6. Once ready, the screen shows:
   - **Status:** Online
   - **Instance URL:** `https://devXXXXXX.service-now.com` (note it down — you'll use this URL for everything
     below)
   - **User name:** `admin`
   - **Current password:** hidden by default; click the eye icon to reveal it. Store this password somewhere
     safe.
7. If the instance already exists but shows a status other than "Online", use the **Refresh** button on the same
   screen; instances hibernated due to inactivity wake back up on their own when accessed, or offer a "wake up"
   option on this screen.

---

## 2. First login to the instance

1. Go to the **Instance URL** you noted in the previous step.
2. Log in with `admin` and the revealed password.
3. On the first login, an onboarding tour appears ("Work your way", "Step 1 of 6"). Close it by clicking the X —
   no need to follow it.

---

## 3. Creating the Incident Kanban board (Visual Task Board)

1. In the top menu, click **All** (opens the application navigator) and search for **Visual Task Boards** (it's
   listed, usually near "Self-Service").
   - Direct shortcut: navigate to `<instance_url>/now/nav/ui/classic/params/target/%24vtb.do`
2. On the "Welcome to Visual Task Boards" screen, click **Create New Visual Task Board**.
3. Choose **Data Driven Board** (not "Freeform Board").
4. Fill in:
   - **Task Table:** search for and select `Incident [incident]`
   - **Vertical Lane Field:** search for and select `State` (there's also "Incident state" — use the plain
     **State** field, it's what reflects the base value used by the Business Rules)
   - **Swimlane Field:** leave blank (optional, not used here)
5. Click **Next**.
6. On the following screen ("Incidents by State" is already suggested as the name), **don't add any filter
   condition** — leave it showing all incidents. Click **Create**.
7. The board opens with automatic columns per `state` value: **New, In Progress, On Hold, Resolved, Closed,
   Canceled** (the Canceled column may be off-screen to the right — you can scroll horizontally). Cards can be
   dragged between columns, which updates the incident's actual `state` field. Once the custom `Prioritized`
   state is added (step 7 below), a new column for it appears automatically — the board is Data Driven off the
   `state` field's choice list, no separate reconfiguration needed.

---

## 4. Creating the orchestrator's service user

1. Go to `<instance_url>/sys_user.do?sys_id=-1` (or **All** → search **Users** → **New**).
2. Fill in:
   - **User ID:** `delphix.orchestrator`
   - **First name:** `Delphix`
   - **Last name:** `Orchestrator`
   - **Active:** checked (default)
   - **Internal Integration User:** check this box (marks it as an integration account, not a human user license)
3. Click **Submit**.
4. Open the newly created record and go to the related **Roles** tab. Click **Edit...**.
5. On the role editing screen, search for `itil` in the search box on the left, double-click it to move it to
   the right-hand list (**Roles List**), and click **Save**.
   - This automatically brings in inherited roles (e.g. `sn_incident_write`, `sn_change_write`, etc.) — that's
     expected, `itil` is the standard analyst role with read/write access on Incident.
6. Back on the user record, click **Set Password** (button at the top, next to "Update") and set a password.
   **Write down the username (`delphix.orchestrator`) and password somewhere safe** — the orchestrator will use
   these credentials (Basic Auth) to call the ServiceNow Table API.

---

## 5. Creating the webhook system property

1. Go to `<instance_url>/sys_properties.do?sys_id=-1`.
2. Fill in:
   - **Name:** `delphix.orchestrator_webhook_url`
   - **Description:** `HTTP endpoint of the Delphix orchestrator (receives Incident state-change events). Update once the service is live.`
   - **Type:** `string`
   - **Value:** an initial placeholder, e.g. `https://REPLACE-ME.example.com/servicenow-webhook` (update later
     with the orchestrator's real public URL)
   - **Ignore cache:** leave checked (default)
3. Click **Submit**.

> Once the orchestrator is live (see [delphix_servicenow_orchestrator_spec.md](delphix_servicenow_orchestrator_spec.md)),
> come back here and edit the **Value** with the real public URL.

---

## 6. Adding the custom "Prioritized" Incident state

The analyst-facing trigger for provisioning is a custom state, **not** the stock `In Progress` — this keeps
`In Progress` meaning "environment ready, investigation under way" (a state the orchestrator itself sets once the
VDB exists), rather than "someone clicked a button."

1. Go to `<instance_url>/sys_dictionary.do?sysparm_query=name=incident^element=state` (or **All** → search
   **Dictionary** → filter **Table** = `Incident`, **Column name** = `state`).
2. Open the dictionary entry for the `state` field.
3. Scroll to the related list **Choices** and click **New**.
4. Fill in:
   - **Label:** `Prioritized`
   - **Value:** `15` (doesn't collide with the stock values: New=1, In Progress=2, On Hold=3, Resolved=6,
     Closed=7, Canceled=8)
   - **Sequence:** leave blank/automatic
5. Click **Submit**.

---

## 7. Creating the provisioning Business Rule (fires on "Prioritized")

1. Go to `<instance_url>/sys_script.do?sys_id=-1` (or **All** → search **Business Rules** → **New**).
2. Fill in:
   - **Name:** `Delphix - Provisionar VDB (Incident Prioritized)`
   - **Table:** search for and select `Incident [incident]`
   - Check the **Advanced** box (this enables the script tab)
3. On the **When to run** tab:
   - **When:** `async` (dropdown — options are before/after/async/display)
   - **Update:** check this box (Insert, Delete, Query stay unchecked)
   - **Filter Conditions:** click **Add Filter Condition** and set: field `State`, operator `changes to`, value
     `Prioritized`
4. On the **Advanced** tab, **Script** field, delete the placeholder content and paste exactly:

```javascript
(function executeRule(current, previous /*null when async*/) {
    try {
        var url = gs.getProperty('delphix.orchestrator_webhook_url');
        if (!url) {
            gs.error('Delphix: delphix.orchestrator_webhook_url property not configured');
            return;
        }
        var body = {
            action: 'provision',
            sys_id: current.sys_id.toString(),
            number: current.number.toString(),
            short_description: current.short_description.toString(),
            description: current.description.toString(),
            opened_at: current.opened_at.toString()
        };
        var request = new sn_ws.RESTMessageV2();
        request.setEndpoint(url);
        request.setHttpMethod('POST');
        request.setRequestHeader('Content-Type', 'application/json');
        request.setRequestBody(JSON.stringify(body));
        var response = request.execute();
        gs.info('Delphix provision webhook status: ' + response.getStatusCode());
    } catch (ex) {
        gs.error('Delphix provision webhook failed: ' + ex.getMessage());
    }
})(current, previous);
```

5. Click **Submit**.

> **Careful when pasting the script:** the ServiceNow code editor already comes with a placeholder template
> (`(function executeRule... { // Add your code here })(current, previous);`). Select all the editor's content
> before pasting, so no template leftovers remain (extra `}` braces break compilation). After saving, if you see
> a "Could not save record because of a compile error" message, it's usually a leftover brace — open the script
> in full screen (expand icon in the editor's toolbar) and check that the number of `{` matches the number of
> `}`.

---

## 8. Creating the teardown Business Rule (fires on "Resolved" or "Canceled")

1. Same screen (`sys_script.do?sys_id=-1`).
2. Fill in:
   - **Name:** `Delphix - Destruir VDB (Incident encerrado)`
   - **Table:** `Incident [incident]`
   - **Advanced:** checked
3. **When to run** tab:
   - **When:** `async`
   - **Update:** checked
   - **Filter Conditions:** two conditions in **OR** with each other:
     - `State` `changes to` `Resolved`
     - OR `State` `changes to` `Canceled`
   - (Use the **OR** button next to the first condition to add the second line — it comes pre-filled with
     "State" and "changes to", just change the value.)
   - **Deliberately no `Closed` condition here**: the orchestrator itself moves the incident to `Closed` once
     teardown finishes. If `Closed` were also a trigger, that transition would re-fire this same rule, sending a
     second (harmless but redundant) teardown call for an incident whose VDB was already deleted.
4. **Advanced** tab, script:

```javascript
(function executeRule(current, previous /*null when async*/) {
    try {
        var url = gs.getProperty('delphix.orchestrator_webhook_url');
        if (!url) {
            gs.error('Delphix: delphix.orchestrator_webhook_url property not configured');
            return;
        }
        var body = {
            action: 'teardown',
            sys_id: current.sys_id.toString(),
            number: current.number.toString(),
            short_description: current.short_description.toString(),
            description: current.description.toString(),
            opened_at: current.opened_at.toString()
        };
        var request = new sn_ws.RESTMessageV2();
        request.setEndpoint(url);
        request.setHttpMethod('POST');
        request.setRequestHeader('Content-Type', 'application/json');
        request.setRequestBody(JSON.stringify(body));
        var response = request.execute();
        gs.info('Delphix teardown webhook status: ' + response.getStatusCode());
    } catch (ex) {
        gs.error('Delphix teardown webhook failed: ' + ex.getMessage());
    }
})(current, previous);
```

5. **Submit**.

---

## 9. Testing (without the orchestrator live yet)

1. Open any existing incident (`<instance_url>/incident_list.do`) or create a new one.
2. Change the **State** field to **Prioritized** and click **Update**.
3. Go to `<instance_url>/syslog_list.do?sysparm_query=messageLIKEDelphix^ORDERBYDESCsys_created_on` (or **All** →
   **System Logs** → **All**, filtering `Message contains Delphix`).
4. An `Information` entry should appear with the message **"Delphix provision webhook status: 0"** — the `0` is
   expected at this point (connection failure because the URL in the system property is still a placeholder).
   What matters is confirming the rule fired without a script error.
5. Go back to the incident, click **Resolve** — ServiceNow will ask for the required fields **Resolution code**
   (e.g. "Solution provided") and **Resolution notes** (any text). Fill them in and confirm.
6. Check the log again — **"Delphix teardown webhook status: 0"** should appear.
7. If both messages show up in the log, the ServiceNow configuration is correct and ready to receive the
   orchestrator's real URL in the system property (step 5).

Once the orchestrator is live and the webhook URL is set for real, the full loop is: analyst sets **Prioritized**
→ orchestrator provisions the VDB and sets **In Progress** → analyst investigates → analyst sets **Resolved** →
orchestrator destroys the VDB and sets **Closed**. The analyst never has to set `In Progress` or `Closed`
manually.

## 11. Important notes / gotchas already found

- **IntegrationHub isn't reliable on PDI/developer instances** — that's why the trigger uses Business Rule +
  `RESTMessageV2` (core ServiceNow API, always available) instead of the Flow Designer's native REST step, which
  depends on IntegrationHub.
- **Passwords should never be typed by an automated assistant/agent** — the "Set Password" steps (the instance's
  admin user and the `delphix.orchestrator` user) need to be done manually by a person.
- **PDIs hibernate due to inactivity** — if the instance shows offline, go back to developer.servicenow.com →
  Manage my instance and use the refresh/wake up button.
- **Only the most recent release is usually available for new instances** at "Request instance" time — older
  releases show up disabled.
- **Business Rule script editor**: always double-check no extra `}` brace is left over from the placeholder
  template after pasting a new script — it's the most common cause of a compile error on save.
- **The orchestrator owns the `In Progress`/`Closed` transitions** — don't add Business Rules that trigger on
  those states, or they'll fire again every time the orchestrator itself sets them.
